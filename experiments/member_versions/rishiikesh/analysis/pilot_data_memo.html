USRP N210 CSI pilot · reference memo

Reading the Pilot Data

What's actually in data/pilot/, how the CSV rows are laid out, and what the project's own comparative analysis against three published WiFi-sensing datasets concluded.

Contents

What's in the folder

Three subjects were recorded — Rishiikesh and Amrith in one room (env A), Gowreesh in another (env B) — each doing four activities: walk, mixed (a mix of motions), stand, sit. That's 12 raw captures, one CSV per (subject, activity).

data/pilot/ P01_action_<subject>_<date>_<activity>.csv # 6 files — walk / mixed P01_noaction_<subject>_<date>_<activity>.csv # 6 files — stand / sit *_check.png # 1 QA plot per capture windows/action|noaction/*.npy # segmented 2s windows, rishiikesh+amrith windows_gowreesh/action|noaction/*.npy # same, gowreesh — kept separate hybrid_model_test-<subject>.pt # trained CNN–GRU–Attention weights hybrid_model_test-<subject>_confusion.csv # 2×2 action/noaction confusion matrix

The label is split across two things: class (action = person moving, noaction = person present but still — not "empty room") comes from the filename prefix; activity (walk/mixed/stand/sit) is the finer label used for the 4-way analysis. Presence is held constant across both classes on purpose, so a model can't cheat by learning occupancy instead of motion.

Format

What's inside a CSV

Every row is one received packet: a timestamp plus the complex channel coefficient for each of the 52 OFDM subcarriers, as real/imaginary pairs. 106 columns total.

The USRP N210 is passively sniffing an existing MacBook ↔ Android hotspot link, not driving its own synchronized transmission. That's why only amplitude (hypot(Re, Im)) is trustworthy: with no shared clock to the two real endpoints, phase is scrambled by carrier/sampling frequency offset and discarded. Every downstream script computes amplitude before doing anything else. Each file also carries exactly one truncated final row (Ctrl+C landed mid-write) — drop it, it's cosmetic, not a data-quality problem.

Derived files

Windows and model outputs

The raw CSVs get cut into fixed-length training examples. Each windows/action|noaction/*.npy file is one 2-second segment, shaped (52, 200) — 52 subcarriers × 200 timesteps — amplitude only, one array per repetition. windows_gowreesh/ holds Gowreesh's segments separately: his data was captured after the comparative analysis below was run and the model was trained, so neither one currently includes him (see the caveat at the end).

The .pt files are trained weights for a CNN–GRU–Attention model, one checkpoint per leave-one-subject-out test split; the matching _confusion.csv is that split's 2×2 action/no-action confusion matrix (rows = true, columns = predicted).

Comparative analysis

Did we collect it correctly?

The headline finding

The model reached 98.4% leave-one-subject-out accuracy on action-vs-no-action — but a single hand-picked number (mean per-window motion energy, one scalar) classifies 99.1% of the same windows with one threshold. The task is genuinely separable (walking/mixed produce 4.2× more motion energy than standing/sitting, and you can see the class difference by eye in the raw traces) but too easy in its binary form to say anything about whether the model or the features are good. The pilot validates the collection pipeline; it doesn't validate the model.

Two other measured results

  • Packet rate is fine for this task, but the segmenter's default wasn't. Actual rate is 51–78 Hz (mean 66.4), comfortably above the 18 Hz where the action/no-action spectra stop being distinguishable (1.4–1.9× headroom). But segment_all_pilot.py ran with its default --rate 100 assumption against 66 Hz data, silently dropping any 2s window that didn't clear a 100 pkt threshold — 13% of windows (48 of 370) lost. Re-running with --rate 50 recovers them with no new capture needed.
  • 52 subcarriers act like about 4 independent ones. Neighbouring subcarriers are correlated at mean |r| = 0.38–0.45 during motion, so the effective rank of the 52-wide covariance is roughly 3.5–4.2 during action and 5.6–25.7 during no-action. A moving body imposes one dominant channel perturbation that most subcarriers see together.

Honest scorecard

✓ Hardware & front-end — matches ARIL spec-for-spec; amplitude-only was the correct call given no phase sync, independently confirmed by ARIL discarding phase too despite having GPS sync.
✓ Class design — person present in both classes forces the model to learn motion, not occupancy; a harder and more useful problem than the trivial version.
✓ Evaluation protocol — leave-one-subject-out is the strictest split of the four datasets compared (UT-HAR: random; ARIL: every 5th sample, same session).
~ Rate stability & window yield — per-second rate dips to 11–55 pkt/s and gaps up to 464 ms; recoverable by fixing the segmenter's rate assumption, not a hardware fault.
~ Subcarrier redundancy — 52 recorded, ≈4 effective dimensions during motion; not free extra data the way a naive per-subcarrier model would assume.
✗ Task difficulty — 99.1% from one scalar means the binary accuracy number proves the pipeline works, not that the model is good.
✗ Scale & diversity — 322 samples, 2 subjects, 1 room, 1 day is 4–800× smaller and far less diverse than any reference dataset; no subject or domain diversity to confirm the result generalises.
✗ Spatial resolution — single-antenna SISO means no antenna-pair phase difference is available even in principle, so Doppler/BVP-style features (what Widar 3.0 uses) are structurally out of reach here.
Verdict: the collection method is sound. Front-end design, the amplitude-only decision, class definitions and evaluation protocol all hold up against published practice. The pilot was a throwaway sanity check and it did its job — it does not show the model, features, or 66 Hz rate will survive a real multi-class task.
Caveat

What's changed since that analysis

The comparative analysis above covers the original 8-capture, 2-subject dataset (Rishiikesh + Amrith, one room). Gowreesh's 4 captures (a second room, env B) were added afterward and are not reflected in that PDF, the trained .pt checkpoints, or the _confusion.csv files — his windows sit in a separate windows_gowreesh/ folder. Re-running the same comparison with all three subjects, and re-training with Gowreesh included, would be the natural next step before treating either result as final.
