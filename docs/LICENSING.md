# Code licensing

Place the approved licence text in **`LICENSE` at the repository root**, next to `README.md` and `NOTICE.md`.

On GitHub, use **Add file → Create new file**, name it `LICENSE`, and select **Choose a license template**. The team/rights holders should agree on the licence before committing it. This privacy cleanup does not select a licence or grant new reuse rights on their behalf.

An MIT licence is one possible choice for independently written, team-owned code if the rights holders want permissive reuse. It must not be used to overwrite the terms of code derived from GNU Radio or other upstream projects. Inspect component licences and ownership before deciding the scope.

Keep existing component LICENSE/COPYING files and copyright notices. Third-party libraries, firmware, vendored code, reference documents and public benchmark resources retain their own terms. A new root licence must clearly distinguish the team's original contributions from those materials.

Raw CSI, participant annotations, individual-event outputs, participant videos, identity mappings, private context/handoff documents and access links are not part of the code distribution. Do not apply a code licence to those excluded materials or infer permission to redistribute them from this repository.

Official guidance: https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository
