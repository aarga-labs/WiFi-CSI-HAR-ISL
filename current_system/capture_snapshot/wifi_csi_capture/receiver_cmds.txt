=====================================================================
 RECEIVER (RX) — USRP N210 #2 at 192.168.10.7
 Two-USRP WiFi CSI capture. Every command, in order.
 Repo root below is written as $REPO. Set it once per terminal:

     REPO=~/adhikkesh/FYP/wifi_csi_capture
=====================================================================

What this side does
-------------------
The USRP only digitises the radio signal and streams raw samples
(20 MS/s) over Ethernet. This laptop runs the whole 802.11 receiver in
GNU Radio, decodes each frame from the transmitter, and writes one CSV
row per frame: Packet, Timestamp_us, Channel, SC0_Re, SC0_Im ... SC51_Im.

  - Receiver flowgraph : $REPO/receiver/gr-ieee802-11/examples/wifi_rx.py
  - CSI block (C++)    : $REPO/receiver/gr-ieee802-11/lib/extract_csi_impl.cc
  - Settings come from environment variables: CSI_TA, CSI_RA, CSI_OUT
  - wifi_rx.py is fixed to Channel 1 (2412 MHz). The transmitter MUST be
    parked on channel 1 (TX_CHANNEL=1), otherwise almost nothing arrives.

1b. HOST TUNING — REQUIRED, or ~99% of frames are lost
---------------------------------------------------------------------
Symptom it fixes (seen on 29 Sep):
    [WARNING] [UDP] The recv buffer could not be resized sufficiently ... 4194304 bytes
    DDDD ... usrp_source :error: In the last 800 ms, 7 overflows occurred.
    -> only 19 CSV rows in 15 s (1.3 rows/s) while the TX sent ~200 frames/s.

Every time (until made permanent):
    sudo sysctl -w net.core.rmem_max=50000000
    sudo sysctl -w net.core.wmem_max=50000000
    sudo cpupower frequency-set -g performance      # Arch/Fedora: package cpupower / kernel-tools
Make the buffer sizes permanent (one-time):
    printf "net.core.rmem_max=50000000\nnet.core.wmem_max=50000000\n" | sudo tee /etc/sysctl.d/90-usrp.conf
    sudo sysctl --system
Check the Ethernet link is 1 Gb/s full duplex (a slow USB adapter causes D's):
    ethtool eno1 | grep -E "Speed|Duplex"        # want: Speed: 1000Mb/s, Duplex: Full
Optional, if the NIC supports it:
    sudo ethtool -G eno1 rx 4096
One-time speed-up for GNU Radio maths kernels:
    volk_profile
Also: laptop on charger, close browsers/IDEs while recording.

---------------------------------------------------------------------
1c. FIND THE RX GAIN — once per room / antenna setup
---------------------------------------------------------------------
Too much gain overloads the receiver (most frames lost even though SNR looks
high); too little loses weak frames. The right value depends on distance and
room, so measure it whenever the antennas move.

Start the transmitter first (TX_CHANNEL=1, PPS=200), keep the room still, then:
    cd $REPO/receiver
    ./gain_sweep.sh              # 20 s per step, gains 0..31.5 dB (~4 min)
It prints rows/s for every gain and suggests the best one, e.g.:
    Best: gain 16 dB  ->  152.3 rows/s
    Record with:  RX_GAIN=16 python3 wifi_rx.py
Write the chosen value down and use it for the whole dataset:
    export RX_GAIN=16            # in every receiver terminal
(If two neighbouring gains are almost equal, take the lower one.)

---------------------------------------------------------------------
2. BUILD + INSTALL THE RECEIVER MODULE
---------------------------------------------------------------------
IMPORTANT: on the RX laptop install ONLY receiver/gr-ieee802-11.
The transmitter's gr-ieee802-11 installs under the SAME name and
overwrites the CSI version (this already happened once, on 4 Sep).
The receiver module already contains every transmitter block, so a
laptop that does both only needs this one (+ gr-foo for TX).

Fresh build:
    cd $REPO/receiver/gr-ieee802-11
    rm -rf build                                  # only if an old/copied build folder exists
    mkdir build && cd build
    cmake ..
    make -j$(nproc)
    sudo make install
    sudo ldconfig

Re-install from an existing build folder (e.g. after something overwrote it):
    cd $REPO/receiver/gr-ieee802-11/build
    make -j$(nproc) && sudo make install && sudo ldconfig

After ANY change to lib/*.cc: run the re-install lines above.
Changes to examples/wifi_rx.py need no rebuild.

8. TROUBLESHOOTING
---------------------------------------------------------------------
No "seen TA=" lines at all
    -> transmitter not running / not parked on channel 1, or no signal:
       check uhd_fft (step 1).
"seen TA=..." but never 02:00:00:00:00:01
    -> you only see other WiFi devices; the transmitter is not on channel 1.
(MATCH) appears but the CSV stays at 1 line
    -> the transmitter version of the module is installed: step 4, then step 2.
Lots of "O" / "D" or "overflows occurred" in the console, very few rows
    -> step 1b (socket buffers + performance governor), then retest for 30 s:
         timeout -s INT 30 python3 wifi_rx.py ; wc -l data/csi_*.csv   (want 3000+ rows)
Few rows even though (MATCH) appears, SNR is high and overflows are rare
    -> signal TOO STRONG (receiver overload). wifi_rx.py uses max RX gain and the
       TX uses gain 30, so antennas that are close clip the ADC and most frames fail.
       Evidence 29 Sep: good capture (3 Sep, 155 rows/s) had mean |CSI| ~0.13;
       bad captures had 0.31 (+8 dB) and ~1.3 (+20 dB).
       Fix: TX and RX antennas 3-5 m apart, not pointing at each other at close range.
       Check for clipping while the TX runs (values near 1.0 = clipping):
         python3 -c "import uhd,numpy as n;u=uhd.usrp.MultiUSRP('addr=192.168.10.7');s=u.recv_num_samps(4000000,2412e6,20e6,[0],31.5);a=n.abs(s);print('max',a.max(),'p99.9',n.percentile(a,99.9))"
       Aim: max well below 0.7. Then check mean |CSI| in the new CSV is near 0.1-0.2.
Every row says Channel 1
    -> expected: wifi_rx.py is fixed to 2412 MHz.
wifi_rx_headless.py / wifi_rx_archieve.py
    -> moved to _archive/ (broken / old channel-hopping version). Use wifi_rx.py.
"Odd decimation", "No GPSDO", "thread priority" warnings
    -> harmless.
"pdu_to_tagged_stream ... Message discarded"
    -> harmless (unconnected debug port).
CMake error "CMakeCache.txt directory ... is different"
    -> the build folder was copied from another path: rm -rf build and build fresh (step 2).
